<Slide title="Flip the flag">

<Column slideOnly>

Your agent's tools already return structured data: emails, events, and tickets. The `mapToolResults` flag adds a **step hook** that reads each tool result as the step finishes and writes it to Neo4j.

Open `workshop.config.ts` and set the flag. Restart `npm run chat` after any change to the config.

The mapper itself, `mapToolResult` in `src/workshop/hooks/mapToolResults.ts`, is a plain function: tool name and output in, a list of nodes and relationships out. Nothing in it calls a model, so the same email always produces the same nodes.

</Column>

<Column slideOnly>

```ts title="In workshop.config.ts"
// STAGE 3: map tool results (emails, events, issues) into graph entities, deterministically.
mapToolResults: true,
```

</Column>

</Slide>

<Slide title="What the mapper writes">

<Column slideOnly>

The mapper keys people by first name, so the calendar, the tickets, and the inbox all agree that `Priya` is one node.

A `get_events` result produces an `Event` node, `ATTENDED_BY` relationships to each attendee, and `ABOUT` relationships to the tickets in the invite. A `get_issue` result produces an `Issue`, `OWNED_BY` its owner, and `BLOCKED_BY` anything blocking it.

Each node also gets its POLE+O label, so an `Issue` is an `:Object` too.

</Column>

```ts title="In src/workshop/hooks/mapToolResults.ts"
export function mapToolResult(tool: string, output: any, people: People = {}): GraphDelta {  // (1)
  // ...
  case "get_events":
    for (const ev of output?.events ?? []) {
      // ... ev.attendees -> ATTENDED_BY
      for (const t of ev.tickets ?? []) {
        d.rels.push({ from: { label: "Event", key: ev.id }, type: "ABOUT", to: { label: "Issue", key: t } });  // (2)
      }
    }
    break;
  // ... issue(): OWNED_BY, BLOCKED_BY  // (3)
}
```
