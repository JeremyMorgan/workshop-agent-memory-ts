## Look at the graph

Open the Neo4j Browser at [http://localhost:7474](http://localhost:7474) and run the query to see the first steps of the session.

Each `Step` links to the messages the model could see and to the tool calls it asked for. Click a `Step` and follow `HAD_IN_CONTEXT` to see its context.

</Column>

<Column slideOnly>

```cypher title="The first steps and their context"
MATCH (st:Step)
WITH st ORDER BY st.sessionId, st.n LIMIT 4
OPTIONAL MATCH (st)-[:HAD_IN_CONTEXT]->(m:Message)
OPTIONAL MATCH (st)-[:REQUESTED]->(tc:ToolCall)
RETURN st, m, tc
```

</Column>

## The agent's account against the record

The agent finished the run by telling you what it did. The harness has its own record of every tool call it received, in `src/workshop/nsuite/audit.ts`: an append-only log with the tool, its arguments, the mode and the outcome.

Put the two side by side. In the scenario, the agent says it deleted ten newsletters and the audit log shows ten `delete_email` calls, so they agree. You can check, and when the two disagree, the record wins.

</Column>

<Column slideOnly>

```text title="The agent said"
agent> Deleted all 10 newsletter emails from your inbox.
```

```bash title="The harness recorded"
npm run state
```

```text title="From the audit log"
#16 delete_email({"id":"e-001"}) mode=mock -> ok
#17 delete_email({"id":"e-002"}) mode=mock -> ok
...
#25 delete_email({"id":"e-010"}) mode=mock -> ok
```

</Column>

## Trace and audit log together

The audit log tells you what happened. The trace tells you what the model could see when it happened.

Each `ToolCall` node carries an `outcome`, so later stages can show blocked calls in the trace too.

</Column>

<Column slideOnly>

```cypher title="Every tool call and what became of it"
MATCH (st:Step)-[:REQUESTED]->(tc:ToolCall)
RETURN st.n AS step, tc.tool AS tool, tc.args AS args, tc.outcome AS outcome
ORDER BY st.n, tc.position
```

</Column>
